# 코드 리뷰 가이드

## 리뷰어 체크리스트

- [ ] 변경 사항이 요구사항과 의도한 동작을 충족하는가?
- [ ] 적절한 테스트가 추가되거나 수정됐고, 테스트가 통과하는가?
- [ ] 정상 흐름과 경계 조건에서 버그나 회귀가 없는가?
- [ ] 불필요한 연산, 메모리 사용, I/O로 성능이 저하되지 않는가?
- [ ] 입력값, 권한, 민감 정보 등 보안 문제가 없는가?
- [ ] 이름과 구조가 이해하기 쉽고 변경 범위가 명확한가?
- [ ] 프로젝트의 코드 스타일과 기존 패턴을 따르는가?
- [ ] 사용자에게 보이는 변경이나 동작 변경에 필요한 문서가 갱신됐는가?

## 리뷰 코멘트 태그

코멘트의 우선순위와 의도를 분명히 하기 위해 다음 태그를 문장 앞에 붙입니다.

| 태그 | 의미 | 예시 |
| --- | --- | --- |
| `[MUST]` | 병합 전에 반드시 수정해야 하는 문제 | `[MUST] 이 입력은 검증 없이 SQL에 포함되어 주입 공격에 노출됩니다.` |
| `[SHOULD]` | 강하게 권장하는 수정이며, 미수정 시 이유를 확인해야 함 | `[SHOULD] 이 반복문은 큰 목록에서 느려질 수 있어 한 번의 조회로 바꾸는 편이 좋겠습니다.` |
| `[NITS]` | 동작에 영향이 없는 사소한 개선 | `[NITS] 변수명을 result보다 userCount로 쓰면 의미가 더 분명합니다.` |
| `[IDEA]` | 당장 필요하지 않을 수 있는 개선 제안 | `[IDEA] 다음 변경에서 이 로직을 공통 헬퍼로 추출할 수 있겠습니다.` |
| `[QUESTION]` | 의도나 동작을 확인하기 위한 질문 | `[QUESTION] 이 경우에는 빈 배열을 반환하는 것이 의도된 동작인가요?` |
| `[PRAISE]` | 좋은 구현이나 선택을 구체적으로 인정 | `[PRAISE] 경계 조건 테스트를 추가해 회귀 가능성을 잘 막았습니다.` |
